== Goal

Project a simple JSON dataset into a human-editable Excel workbook, edit it,
then re-import it back to JSON — with no data loss.

No FK helpers. No cross-tables. Just the structural baseline.

== Source Data

`data/acme_plain/employees.json` — one table, six rows, four columns.

[source,json]
----
[
  { "id": "E001", "name": "Alice Fontaine",
    "department": "Engineering", "location": "Berlin" },
  { "id": "E002", "name": "Bob Hartmann",
    "department": "Sales", "location": "Munich" },
  ...
]
----

== Forward Run

[source,bash]
----
./run_demo.sh pipelines/acme_01_plain_forward.yaml
----

Or with `make`:

[source,bash]
----
make run PIPELINE=pipelines/acme_01_plain_forward.yaml
----

Produces: `tmp/acme_01_plain.xlsx`

== Pipeline Config

`pipelines/acme_01_plain_forward.yaml`

[source,yaml]
----
io:
  input:  { kind: json_dir, path: ./data/acme_plain }
  output: { kind: xlsx,     path: ./tmp/acme_01_plain.xlsx }

excel:
  auto_filter: true
  freeze_header: true
  header_fill_rgb: DDDDDD

pipeline: []
----

No transformation steps — just the raw projection.

== Inspect the Spreadsheet

Open `tmp/acme_01_plain.xlsx`.

You will see:

* One `employees` sheet with frozen header and auto-filter
* A `_meta` sheet (workbook configuration — do not edit)

Edit a row: change a department name or location.

== Reverse Run

[source,bash]
----
./run_demo.sh pipelines/acme_01_plain_reverse.yaml
----

Writes returned JSON to: `tmp/acme_01_roundtrip/employees.json`

The `_meta` sheet drives the re-import. Your edits are reflected in the
returned JSON; the `_meta` sheet is stripped from the output.

== Inspect Returned JSON

`tmp/acme_01_roundtrip/employees.json` is structurally identical to the
source — only the values you edited will differ.

The pipeline is intentionally empty in both directions: no transformation
steps means no hidden transformation, no data loss, and a deterministic
roundtrip.

== Why FK Helpers Come Next

The plain roundtrip works — but reading this spreadsheet is still hard.

The `department` column contains a bare string. In a real model, departments
would be a separate table with their own attributes (budget, head count, etc.).
As the model grows, users need to see related information next to the FK column,
not just the raw ID.

Slice 2 adds FK helper columns: derived display columns that appear beside
their FK in the spreadsheet, are stripped on re-import, and are rebuilt
deterministically from the referenced table on every forward run.
