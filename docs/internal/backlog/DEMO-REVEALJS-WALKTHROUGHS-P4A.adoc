== DEMO-REVEALJS-WALKTHROUGHS-P4A -- Add guided walkthrough slides

*Status:* Open
*Area:* User-facing demo documentation

=== Purpose

Provide click-through walkthroughs for the demo journeys without committing
generated HTML.

The source should be AsciiDoc so that a walkthrough can be reviewed as text,
while the published form can be Reveal.js slides.

=== Scope

* Add `docs/slides/` for Reveal.js AsciiDoc sources.
* Use one slide deck per user journey, not one deck per internal feature.
* Keep code blocks copy-pasteable:
  - run this pipeline
  - open this workbook
  - inspect these sheets/cells
  - re-import or verify this output
* Add local preview/build notes.
* Add a GitHub Pages publishing path that builds HTML as an artifact.

=== Acceptance

* At least one journey has a slide deck source.
* Generated HTML is not committed.
* README or `docs/index.adoc` can link to the published deck once Pages is set
  up.
* The deck names match the automated journey/test names.
* The publishing path supports versioned documentation snapshots for beta/demo
  releases instead of replacing the only public copy.

=== Pages Decision

Preferred path: publish from this repository with GitHub Actions and Pages
artifacts. A separate `spreadsheet-handling-demo-pages` repository is not
required unless repository policy later forces separation.

The source-of-truth stays in Git:

* current editable documentation: `docs/**/*.adoc`
* slide sources: `docs/slides/**/*.adoc`
* generated HTML: build artifact only

For published HTML, prefer stable versioned paths:

* `/latest/` for the current published demo state
* `/versions/v0.1.0b5-demo/`
* `/versions/v0.1.0b6-demo/`

GitHub Pages can serve these paths from one site. The implementation can either
build the complete site artifact from known tags, or maintain a generated
`gh-pages` branch with versioned subdirectories. In both cases, generated HTML
does not belong on `main`.
